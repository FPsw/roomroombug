# 0001. 서버 없이 Supabase로 시작한다

- 상태: 채택
- 날짜: 2026-11-14

## 상황

웹 화면, 데이터 수집 워커, DB가 필요하다. 별도 API 서버(Spring Boot 등)를 처음부터 둘지 정해야 한다.
v0.x의 데이터는 관심종목 50개 × 10년 일봉 ≈ 12만 행으로 작다.

## 결정

DB·인증은 Supabase(Postgres)를 쓰고, API 서버는 만들지 않는다.

- 웹(Next.js)은 서버 측에서 Supabase를 직접 읽는다. 브라우저에는 publishable 키만 가고, 권한은 RLS로 막는다.
- 워커(Python)는 secret 키로 DB에 직접 쓴다.
- 웹과 워커는 서로를 호출하지 않는다. DB 테이블이 두 쪽의 계약이다.
- 사용자는 나 하나다. 회원가입을 막고(`enable_signup = false`), 모든 테이블에 RLS를 켜서 로그인한 사용자만 읽게 한다.

## 버린 선택지

- **처음부터 Spring Boot + AWS**: 지금 요구사항에는 서버가 할 일이 없다. 할 일 없는 서버를 운영하게 된다.
- **로컬 Postgres만 사용**: 배포된 웹에서 접근하려면 결국 터널이나 서버가 필요하다.

## 결과

- 바로 시작할 수 있고, 인증·RLS·마이그레이션 도구가 같이 온다.
- 표준 Postgres라 `pg_dump`로 옮길 수 있어서 나중에 바꾸는 비용이 작다.
- 무료 플랜은 DB 500MB라 v1.0(전 종목 10년 일봉)에서 부족해진다. 그때 DESIGN.md 7.6의 선택지 중 하나를 골라 새 ADR로 남긴다.
- 1주일 비활성 시 프로젝트가 일시정지된다. 매일 수집 작업이 쓰기를 하면 걸릴 일이 거의 없다.
